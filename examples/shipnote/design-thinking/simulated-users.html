Notes marked Simulated come from Claude role-playing the personas in the simulated user panel, not from real people. Use them to move fast and to sharpen questions, then validate what matters with real users.

The panel

Four release engineers who would run shipnote at the end of a release. Grounded only where the README is: the sprint-end draft (S1), unlabeled PRs landing in Other (S2), and regulated teams needing a sign-off trail (S3). Everything else is invented.

Juno Marchetti

SU-1

Release engineer, 8 months, 40-person startup (scheduling app)

“Sorry, this is probably really obvious stuff.”
Goals
Publish notes with nothing embarrassing in them; learn what “good” looks like.
Pains
Doesn’t know what’s safe to leave out; uneasy chasing senior engineers; gets no feedback.
Context
Moved over from QA. Inherited release duty and a runbook from a predecessor. Releases every second Friday.
Tools
shipnote per the runbook, GitHub, Jira, Slack, last release’s notes to copy wording from.
Talks
Earnest, hedges (“I think?”), apologizes, gives long detailed answers.
Never says
“That’s not my problem.”
Grounded in
S1 sprint-end draft; S2 unlabeled PRs. Rest invented.

Odile Brennan-Kask

SU-2

Release manager, 11 years, medical-device software (regulated)

“Prose I can fix. Provenance I can’t.”
Goals
Every line traceable to an approved change request; audits with no findings.
Pains
Untraced merges found late; sign-off lives outside GitHub; a CAPA over a typo fix.
Context
Six-week releases. Notes are a controlled document. Regulatory affairs and QA sign off in the quality system.
Tools
shipnote for the PR list only, a Word template under document control, the change-control system, a PR-to-change-request spreadsheet.
Talks
Formal, precise, unhurried; regulatory vocabulary; skeptical of anything that writes on the team’s behalf.
Never says
“Good enough, ship it.”
Grounded in
S3 sign-off trail; S1 draft. Rest invented.

Teo Abara

SU-3

Release engineer, 5 years, 120-engineer B2B SaaS (invoicing), monorepo

“The draft’s fine. It’s the inputs that are garbage.”
Goals
Ship Thursday with notes nobody calls about; spend less of Wednesday night on Other.
Pains
Half the PRs unlabeled; rewriting PR titles for customers; blamed for lines they didn’t write.
Context
Two-week sprints, merge freeze Wednesday, release Thursday. PM wants highlights; CS gets a heads-up copy.
Tools
shipnote, a browser tab per PR, Slack, a personal file of stock phrases.
Talks
Terse, dry, quotes numbers, mild sarcasm, impatient with process talk.
Never says
“Let’s set up a meeting about it.”
Grounded in
S1 sprint-end draft; S2 Other bucket. Rest invented.

Mateus Corvin

SU-4

Volunteer maintainer of an open-source library, 3 years, Brazil-based

“I already stopped. Not the tool’s fault.”
Goals
Release when it’s ready without losing the weekend; notes strangers can understand.
Pains
External contributors never label; English is a second language and the notes are public; only evenings and weekends.
Context
No sprints; releases every one to three months; about 40 contributors a year, most one-time.
Tools
git log, GitHub Releases, a translator to check phrasing. Tried shipnote once and went back to writing by hand.
Talks
Friendly, tired, short answers, occasional non-native phrasing.
Never says
“Our release process requires…”
Grounded in
S2 unlabeled PRs. Rest invented.

“Last Friday. I ran the shipnote thing like Dana’s runbook says, then went through all of it with Jira open. Fourteen in Other. I think I got them right? Took most of the afternoon, sorry, that’s probably slow.”

Key takeaways

  1. Four release engineers span novice to expert, startup to regulated to open source, and champion to lapsed user.
  2. All four depend on PR authors they can’t control; they differ on what “done” means for the notes.
  3. SU-4 works without sprints or a team, so is probably a different user from SU-1 to SU-3.

Validate next

  • Simulated Most persona traits are invented. Only the sprint-end draft (S1), unlabeled PRs (S2) and the sign-off trail (S3) are grounded.
  • Question Does shipnote have open-source or volunteer users at all? If not, retire SU-4.
